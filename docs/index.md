## Decisions

Short records of choices that were genuinely contested. Each says what was
decided, what else was considered, and what would make us revisit it.

| Record | Subject |
|---|---|
| [0001](decisions/0001-no-second-password-hash.md) | No `password_hash` column; PIN hashes live in a private schema |
| [0002](decisions/0002-money-is-bigint-minor-units.md) | Money is `bigint` minor units, not `integer` |
| [0003](decisions/0003-shortfall-treatment-is-a-generated-column.md) | `shortfall_treatment` is generated by Postgres, not by the data layer |
| [0004](decisions/0004-driver-identity-images-via-rpc.md) | Driver identity images are read through a function, not a column grant |
| [0005](decisions/0005-append-only-with-an-allow-list.md) | What "append-only" freezes and what it lets move |
| [0006](decisions/0006-status-changes-are-events.md) | Status columns are projections of an event table |

## Build order

From SPEC section 9. Each phase ends with something usable; the next does not
start until the current one runs.

1. **Foundation** — repo, stack, database schema, migrations, seed data. ← *done*
2. Auth and permissions — email/password for desktop, PIN for mobile
3. Vehicles and Drivers
4. Records spine — ledger, activity records, corrections, audit log
5. Daily payments — the five outcomes, shortfall, overpayment, bundles, balances
6. Maintenance — orders, statuses, parts, status events
7. Alerts — with working deep links
8. Accounting — clickable cards and analytics
9. Offline sync — queue, idempotency, pending indicators
10. Future Purchases
11. Export, settings, polish
